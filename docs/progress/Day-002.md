## ✅ Major Architectural Shift

Originally:

```
PDF
↓

Questions
```

Now:

```
PDF

↓

Concepts

↓

Knowledge Graph

↓

Learning Graph

↓

Personalized Questions
```

This changes the entire architecture of EKE.

---

## ✅ Knowledge Graph

Realized that educational concepts are connected.

Instead of storing chapters, EKE stores relationships.

Example:

Fractions

↓

Equivalent Fractions

↓

Comparing Fractions

↓

Addition of Fractions

↓

Decimals

Each Concept may have:

- multiple prerequisites
- multiple dependent concepts
- cross-subject relationships

---

## ✅ Learning Graph

One of today's biggest insights.

Knowledge is shared.

Learning is personal.

Example:

Knowledge Graph

```
Equivalent Fractions
```

exists once.

Each student has their own relationship with it.

Example:

Meera

- Mastery: 92%
- Confidence: 78%
- Preferred Style: Visual
- Misconception:
  Bigger denominator means bigger fraction.

Radha

- Mastery: 25%
- Loves stories
- Needs concrete objects

The same Concept supports different learning journeys.

---

# Architecture Decisions

## We do NOT store questions.

Instead we store:

- Concepts
- Teaching strategies
- Misconceptions
- Question templates

Questions are generated dynamically by the Quiz Engine.

---

## Separation of Responsibilities

Knowledge Engine

↓

Knowledge Graph

↓

Student Engine

↓

Quiz Engine

↓

Gamification Engine

Every engine has one responsibility.
